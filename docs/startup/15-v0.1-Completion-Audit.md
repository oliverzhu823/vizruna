## 1. 一句话结论

v0.1 的仓库内 P0 工程实现、自动化测试、8 小时长运行、性能基线、依赖审计、
未签名打包和发布脚本已经形成闭环；但产品还不能标记为“正式 v0.1”或分发给
客户，因为许可证书面结论、Apple 正式签名公证、干净设备、真实 Provider
推理、7 天内部试运行、真实异常演练、3–5 人试点和发布签署都需要外部人员、
凭据或设备完成。

这两个结论不矛盾：

- **工程候选版完成**：在代码仓库内能安全、可重复完成的工作已经完成。
- **正式发布未完成**：PRD 第 12 节的外部发布条件尚未全部取得证据。

## 2. 状态口径

| 状态 | 含义 |
| --- | --- |
| Pass — automated | 由当前仓库自动化或确定性集成重复验证 |
| Pass — baseline/regression | 从固定 pi-app 底座继承，并由回归门禁保护 |
| Conditional | 工程实现通过，但真实凭据、设备或人工场景仍待验证 |
| External pending | 不能由当前开发环境诚实代替的外部门禁 |
| Delivered phase 1 | 产品负责人确认纳入第一阶段，工程实现与自动化已完成 |

“有脚本”不等于“外部门禁通过”；“无真实凭据的网络测试”也不等于“真实模型
推理通过”。

## 6. 非功能要求审计

### NFR-01 稳定性

- Worker 崩溃隔离、2 秒内状态语义、JSONL 写入边界和脏 Worktree 保护均有自动化。
- 8.014 小时生产 Electron 看门狗无意外退出。
- 100 个子任务最终为 0 活跃 Runtime 槽。
- 100 次租约启动/退出循环无有效持有者误接管。
- 仍需 7 天真实内部试运行和一次人工可复核的异常恢复演练。

### NFR-02 性能

参考设备为 Apple M4、24 GB、macOS arm64、Node.js `22.19.0`，20 轮生产构建：

| 指标 | 结果 | 阈值 | 状态 |
| --- | ---: | ---: | --- |
| 冷启动 P95 | 1424.42 ms | ≤ 5000 ms | Pass |
| 项目/会话列表 P95 | 48.14 ms | ≤ 2000 ms | Pass |
| 会话切换 P95 | 44.25 ms | ≤ 1000 ms | Pass |
| Composer 渲染 P95 | 0.20 ms | ≤ 100 ms | Pass |
| Main→UI 绘制机会 P95 | 17.60 ms | ≤ 500 ms | Pass |
| 取消信号 P95 | 2.50 ms | ≤ 1000 ms | Pass |
| 冷启动空闲工作集 P95 | 495.28 MiB | ≤ 570.60 MiB | Pass |

内存上限来自相同设备、固定上游提交的 M0 P95 `475.50 MiB × 1.20`；当前增长
`4.2%`。四个真实模型回合并行时的用户交互需在真实凭据/试点中确认，不能由
四个确定性测试替身完全代替。

### NFR-03 安全

- Renderer 保持 sandbox/context isolation，未开放 Node。
- Renderer 不直接获得文件系统、Shell 或 safeStorage。
- 新增 IPC 有共享契约、allowlist 和 Zod 运行时校验。
- Provider 代理密码使用 safeStorage；Pi 凭据沿用 Pi 认证存储。
- 外链/Markdown/工具输出按不可信输入处理。
- Worktree Git 与文件操作限定在规范化受管根。
- 新鲜完整与生产 npm audit 均为零漏洞；SBOM 和生产依赖许可证清单可生成。
- pi-app 商业使用与再分发许可已经确认；候选包仍须通过随包声明和 SBOM 复核。

### NFR-04 兼容与 NFR-05 可维护

- Pi JSONL Schema 未改变，产品元数据独立 SQLite。
- 中英文、空格和非 ASCII 路径进入测试。
- 首发平台保持 macOS Apple Silicon。
- 未引入第二套全局状态容器；新建任务临时状态仅在对话框局部。
- Lease、Worktree、Orchestration、Provider Route 均为独立模块和测试。
- Pi SDK 固定为当前已测 latest `0.82.1`；外部 SDK 最低为 `0.82.1`，并通过 ModelRuntime 能力门禁后才允许加载。

任何 S0/S1、代理误路由、凭据泄漏、数据损坏、错误删除或 Gatekeeper 绕过都
直接触发 No-Go。

上述人工证据由 `release-evidence/<version>.json` 在本地汇总，并使用
`npm run release:evidence:status` 随时查看缺项；正式 Tag 前必须运行
`npm run release:evidence:check`。校验器会绑定当前版本和 commit、拒绝疑似
密钥/Token、验证七天跨度、3–5 人与角色覆盖、独立复核和四方签署。它不能
替代真实执行或负责人判断，因此当前没有证据时仍保持 External pending。

公司发布基础设施另由 `npm run release:readiness:status` 做只读检查；它核对
公司 remote、受保护环境、签名 Secret 名称、证据绑定、候选 Run 与未过期
Artifact。正式 Tag 前 `npm run release:readiness:check` 也必须为 Go。
