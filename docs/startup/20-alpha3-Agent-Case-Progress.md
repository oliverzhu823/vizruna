## 1. 本轮目标

本轮不是建设客户 Runtime，而是解决 Studio 阶段最重要的资产断层：以前一次对话跑通后只留在会话列表中，无法说明它是否值得复用、是否经过验证、属于什么业务案例。

alpha.3 引入 Agent Case，把“对话”提升为“待继续验证的产品案例”，但仍保留对原会话的引用，不提前复制和打包全部内容。

## 3. 数据和安全边界

Agent Case 当前只保存产品索引，不保存：

- 完整提示词和模型回复；
- API Key、OAuth Token、Cookie；
- 代理账号和密码；
- 对话附件的内容副本；
- 可在客户环境直接运行的冻结配置。

原会话正文继续由 Pi JSONL 管理。Agent Case 保存源工作区和源会话引用，因此它目前是 Studio 资产，不是可销售的 Agent Package。

## 5. 产品负责人验收步骤

1. 在开发模式中打开一个真实项目和已有会话。
2. 从左侧底部点击“Agent 案例”。
3. 点击“沉淀当前对话”，填写名称、说明和标签并保存。
4. 确认卡片显示正确的项目、模型、标签和“待验证”。
5. 点击“打开原对话”，确认返回正确工作区和正确会话。
6. 再次进入案例页，将它标记为“已验证”。
7. 归档该案例，确认默认列表隐藏；打开“显示已归档”并恢复。
8. 切换白色、黑色和鼠尾草主题，检查可读性和操作层级。

## 6. 下一轮建议

人工验收通过后，alpha.4 只扩展“复测案例”的闭环：目标、输入样例、预期产物、验收清单、复测运行和结果记录。至少两个真实案例重复跑通前，不启动 `.vizagent` 导出和独立 Runtime 开发。
