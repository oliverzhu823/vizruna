## 1. 验收原则

本项目不以“界面能点”作为验收依据。每项 P0 能力必须同时证明：

1. 正常路径能够完成。
2. 失败路径不会破坏会话、代码和凭据。
3. 应用重启后状态可以解释和恢复。
4. 用户能够看到结果、证据和下一步行动。
5. 自动化测试能够重复验证关键约束。

## 2. 验收环境

### 2.1 必测环境

- 当前受支持的 macOS Apple Silicon 正式版本。
- 一台未安装 Node.js、Git GUI 或开发版应用的干净测试设备。
- 一个包含提交历史、未提交改动、未跟踪文件和多个分支的 Git 测试仓库。
- 至少一个需要代理访问的国际 Provider。
- 至少一个要求直连的中国 Provider。
- 中英文系统语言各一次完整核心流程。

### 2.2 测试数据

- 测试专用 API Key，不使用生产客户凭据。
- 测试会话包含短会话、长会话、工具调用和中断会话。
- Git 测试仓库必须可以整体重建，不用真实业务仓库做破坏性测试。
- 故障注入数据与正常使用数据分开存放。

## 4. 质量门禁

| 门禁 | 内容 | 通过标准 |
| --- | --- | --- |
| G1 静态质量 | 格式、lint、类型检查、循环依赖检查 | 零错误 |
| G2 自动化测试 | 单元、契约、进程集成 | 全部通过；不允许重跑后“碰巧通过” |
| G3 端到端 | 核心用户流程和失败流程 | P0 用例 100% 通过 |
| G4 数据完整性 | JSONL、SQLite、Git、租约一致性 | 无不可恢复损坏或静默丢失 |
| G5 稳定性 | 长运行、并发、取消、资源释放 | 达到第 11 节阈值 |
| G6 安全 | 凭据、IPC、日志、依赖和导出包 | 无阻断级或严重级问题 |
| G7 产品质量 | 中英文、错误提示、可访问性 | 核心流程无缺失或阻断 |
| G8 发布质量 | 构建、签名、公证、安装、升级、卸载 | 干净设备完整通过 |

任何门禁失败，均不得用“已知问题”替代验收通过；只能修复、明确降级并移出发布范围，或做 No-Go 决策。

- G1–G7 的仓库内自动化与 M4 长运行证据已通过；最终候选已在 Node.js `22.19.0` 下重跑完整 `npm run verify`、桌面 E2E、真实网络路由 E2E、干净 `npm ci` 和打包应用冷启动烟测。
- `npm run verify` 包含 286 个脚本/契约测试、290 个单元测试、生产构建和 341 个生产组件 SBOM；`npm audit --omit=dev` 为 0 个生产依赖漏洞。
- Provider 真实网络路径已验证显式 HTTP 代理与 direct 隔离；确定性回环集成已验证 SOCKS5、SOCKS5H、`NO_PROXY` 和运行时换路由，均未携带 Provider 凭据或发起收费推理。

- 完整状态和解除条件见 `11-M5-Productization-Report.md`。

## 5. M0 验收：基线与合规

### AC-M0-01 可复现构建

- 给定一台符合文档要求的开发设备。
- 按 README 执行安装、构建和启动步骤。
- 应得到可启动的开发版应用，且不需要维护者机器上的隐式全局依赖。

### AC-M0-02 数据目录隔离

- 同时安装原 pi-app 和新产品。
- 两者分别创建会话和配置。
- 新产品不得覆盖、迁移或删除原应用数据。

### AC-M0-03 依赖和许可证

- 所有直接生产依赖均可生成名称、版本和许可证清单。
- pi-app、pi-gui 和 Pi SDK 的使用方式具有书面结论。
- 无许可证或许可证不明的代码不得进入发布构建。

### AC-M0-04 SDK 适配边界

- 搜索产品业务代码时，不应出现绕过统一适配层的大量 Pi SDK 直接调用。
- 升级 SDK 时，兼容修改应主要集中在适配层和契约测试。

## 6. M1 验收：会话租约

### AC-M1-01 单写保护

- 给定同一会话已经由 Worker A 持有有效租约。
- Worker B 请求写入该会话。
- B 必须被拒绝或进入只读模式，不能向 JSONL 追加内容。

### AC-M1-02 正常释放

- Worker 正常结束或用户关闭会话。
- 租约被释放。
- 另一 Worker 可以立即获得租约并继续会话。

### AC-M1-03 崩溃恢复

- 在 Worker 持有租约时强制终止其进程。
- Main 进程根据 PID、心跳和超时规则判断租约失效。
- 用户确认后可以恢复写入，不需要手工删除租约文件。

### AC-M1-04 不允许无提示接管

- 有效持有者仍存活时尝试强制接管。
- 界面必须显示会话、持有进程、风险和可选动作。
- 未经明确确认，不得变更租约。

### AC-M1-05 审计

- 获取、续期失败、释放、过期和强制接管均产生审计事件。
- 审计事件不包含对话正文和凭据。

## 7. M2 验收：Worktree 生命周期

### AC-M2-01 创建成功

- 给定一个正常 Git 仓库和一个合法任务名称。
- 创建 Worktree。
- Git 实际工作树、分支、SQLite 登记和界面状态必须一致。

### AC-M2-02 创建失败回滚

- 在目录创建、Git 命令或数据库写入阶段注入失败。
- 系统不得留下被标记为 ready 的半成品。
- 能自动回滚时应回滚；不能回滚时应标记 error 并给出修复动作。

### AC-M2-03 脏状态保护

- Worktree 包含未提交或未跟踪文件。
- 用户执行删除。
- 默认操作必须被阻止，并列出风险；强制操作需要二次确认和审计。

### AC-M2-04 恢复扫描

- 应用关闭期间，从命令行添加、移动或删除一个受管 Worktree。
- 应用重启后扫描实际状态。
- 界面不得继续显示虚假的 ready 状态，应标记差异并提供处理选项。

### AC-M2-05 批量稳定性

- 连续创建、使用和安全回收 20 个 Worktree。
- Git worktree 列表、磁盘目录和 SQLite 无孤儿记录。

### AC-M2-06 非 Git 目录

- 在非 Git 项目中请求隔离任务。
- 系统明确说明无法创建 Worktree，并允许在用户确认后使用独立普通目录或取消。
- 不得伪装为已隔离。

## 8. M3 验收：多 Agent 编排

### AC-M3-01 父子任务闭环

- 父 Agent 创建两个子任务。
- 两个子 Agent 分别在独立 Worktree 中完成代码修改和测试。
- 父 Agent 收到结构化结果，包括状态、摘要、变更文件和测试证据。

### AC-M3-02 并发限制

- 将最大并发设置为 4。
- 同时请求创建 6 个子 Agent。
- 最多只有 4 个 Worker 运行，其余任务排队且状态明确。

### AC-M3-03 子任务失败隔离

- 强制让其中一个子 Worker 崩溃。
- 其他 Worker、父 Agent 和主应用保持运行。
- 失败任务状态为 failed 或 interrupted，不得显示 success。

### AC-M3-04 取消传播

- 父任务运行时发出取消。
- 未开始任务不再启动，运行中子任务收到取消信号。
- 超时未退出的 Worker 被按策略终止，所有最终状态可解释。

### AC-M3-05 超时

- 子任务超过配置的执行时间。
- 系统发出超时事件并提供重试、继续等待或取消选项。
- 不得永久停留在 running。

### AC-M3-06 重启恢复

- 多个子任务运行时强制退出桌面应用。
- 重启后显示上次任务树、会话和 Worktree。
- 无法继续的任务标记 interrupted；允许恢复的任务需要用户明确发起恢复。

### AC-M3-07 事件一致性

- 模拟事件重复、延迟和乱序。
- UI 根据任务 ID 和序号去重或拒绝旧事件。
- 任务最终状态与 Worker 实际状态一致。

### AC-M3-08 证据真实性

- 子 Agent 报告测试通过时，证据必须包含执行命令、退出码、时间和工作区。
- 没有执行测试时必须明确标记“未验证”，不得自动生成“已通过”。

实施状态：M3 内部工程门禁已于 2026-07-25 通过；自动化覆盖两个真实 Git Worktree 的代码与测试闭环、4/6 并发排队、Worker 失败隔离、递归取消、超时、重启恢复、事件乱序和退出码证据，详见 `09-M3-Multi-Agent-Orchestration-Report.md`。真实外部 Provider 复测保留到 M5 Provider 独立路由门禁。

## 9. M4 验收：恢复、审计和诊断

### AC-M4-01 统一失败状态

以下故障都必须结束于明确状态和用户动作，不能无限加载：

- 模型请求断网。
- Provider 返回鉴权或地区限制错误。
- Worker 意外退出。
- Worktree 路径不可用。
- 磁盘空间不足或写入失败。
- SQLite 暂时锁定或损坏。

### AC-M4-02 诊断包脱敏

- 导出诊断包前展示所含文件和字段。
- API Key、Cookie、Authorization Header、代理密码和完整对话正文不得出现。
- 自动化测试使用诱饵密钥检查导出包。

### AC-M4-03 元数据恢复

- 备份 SQLite 后模拟数据库不可读。
- 产品不得改写 Pi JSONL 以“修复”元数据。
- 从备份恢复后，Agent 关系、Worktree 登记和审计索引可用。

### AC-M4-04 状态对账

- 故意制造 SQLite、Git Worktree 和磁盘目录不一致。
- 恢复工具列出差异、建议动作和风险。
- 未经确认不得删除代码目录或分支。

实施状态：AC-M4-01–04 已通过，详见 `10-M4-Stability-Audit-Diagnostics-Report.md`。生产 Electron 已验证诊断预览、正常元数据恢复、损坏备份拒绝和活动数据库保持完整；100 个连续子任务最终无活跃 Runtime 槽；真实 Electron 看门狗运行 8.014 小时无意外退出。

## 10. M5 验收：Provider、代理、终端和发布

### AC-M5-01 Provider 独立路由

- Provider A 配置为指定代理，Provider B 配置为直连。
- 分别发起请求。
- A 的 Worker 环境使用指定代理，B 的 Worker 环境没有该代理变量。

### AC-M5-02 不影响其他软件

- 产品运行前后记录系统代理设置。
- 在产品内切换 direct、system 和 profile。
- 产品不得修改 macOS 全局代理，也不得改变其他终端或应用的环境。

### AC-M5-03 路由可解释

- 使用 DNS、TCP、TLS、代理握手或 Provider 非推理接口执行连通性测试，不发送模型推理请求。
- 结果显示目标 Provider、路由模式、代理配置名称和错误类别。
- UI 与日志不得显示代理密码或完整 API Key。

### AC-M5-04 Provider 切换

- 在同一项目中从国际 Provider 切换到中国 Provider。
- 新启动的 Worker 使用新 Provider 的路由。
- 已运行 Worker 的行为遵守“当前任务保持或明确重启”的产品规则，不允许静默改变。

### AC-M5-05 终端隔离（第一阶段发布门禁）

- 分别打开项目根目录终端和子 Agent Worktree 终端。
- 初始工作目录正确。
- 关闭终端、shell 异常退出或大量输出，不影响 Agent Worker 和主进程。

### AC-M5-06 授权失败提示（第一阶段发布门禁）

- 模拟 OAuth 回调失败、地区限制和超时。
- 用户看到具体错误类别、当前路由和可选替代方案。
- 不得只显示“登录失败”。

### AC-M5-07 中英文

- 在应用内切换语言，无需重启即可更新核心界面。
- 菜单、对话框、任务树、错误、设置和安装引导无缺失键。
- 未翻译键由 CI 检测，不直接把资源键展示给用户。

### AC-M5-08 干净设备安装

- 在未安装开发依赖的受支持 macOS 设备上安装签名版本。
- 系统安全检查通过，应用首次启动成功。
- 完成 Provider 配置、打开项目、一次 Agent 任务和一次应用重启恢复。

### AC-M5-09 升级和卸载

- 从上一个试点版本升级到候选版本。
- 会话、配置和元数据保留，数据库迁移可回滚或有备份。
- 卸载应用不默认删除用户项目、Pi JSONL 和 Worktree。

### AC-M5-10 流式对话工作台

- 流式文本、Markdown、代码块和工具调用卡片在长输出下持续更新。
- 用户滚动查看历史时，不被强制拉回底部。
- 工具输出和 Markdown 中的不可信内容不能执行脚本或绕过外链确认。

### AC-M5-11 附件输入

- 文件选择、拖放、图片粘贴均能形成可见附件。
- 不支持、过大或读取失败的文件给出明确提示。
- 发送前删除附件后，Worker 不得继续收到该附件。

### AC-M5-12 文件、Diff 和 Review

- 文件树可以打开中英文、空格路径文件并使用多标签查看。
- Agent 修改后能显示目标 Worktree 中的实际 Diff。
- Review 操作不直接覆盖用户文件，应用重启后仍能重新读取真实状态。

### AC-M5-13 会话树操作

- 会话列表、Fork、Clone 和 Rewind 在测试会话中各执行一次。
- 操作结果继续符合 Pi JSONL 会话语义，原 Pi CLI 可以读取。
- 破坏性或丢弃后续内容的操作需要明确确认。

### AC-M5-14 Skills、扩展和 Adapter

- 可以查看、启用或配置底座已支持的 Skills、扩展和 Adapter。
- 扩展异常不导致主窗口退出，并显示其来源和错误。
- 未受信任扩展的本地代码执行边界有明确提示。

### AC-M5-15 国内外自定义 Provider

- 至少配置一个国际 Provider 和一个中国 Provider，并分别完成非推理连通性测试。
- Provider、模型、凭据引用和路由选择重启后保持。
- 删除 Provider 配置不在日志或数据库留下明文凭据。

### AC-M5-16 通知和后台运行

- Agent 在窗口未聚焦时完成或等待输入，系统通知按用户设置触发。
- 关闭窗口、隐藏应用和退出应用的行为符合明确设置。
- 后台运行中的会话不会因 Renderer 销毁而被错误标记完成。

## 11. 非功能验收阈值

以下是 v0.1 的首轮目标，M0 性能基线完成后允许通过 RFC 修订，但不得在发布时临时放宽。

### 11.1 性能与资源

| 指标 | v0.1 目标 |
| --- | --- |
| 冷启动到主窗口可交互 | P95 不超过 5 秒 |
| 已有项目会话列表首次显示 | P95 不超过 2 秒，不读取所有会话全文 |
| 用户取消到 Worker 收到取消信号 | P95 不超过 1 秒 |
| 任务事件进入 Main 到 UI 可见 | P95 不超过 500 毫秒 |
| 空闲主应用内存 | 建立 M0 基线后，回归增长不超过 20% |
| 单 Worker 退出后的资源释放 | 30 秒内进程消失、租约释放或进入明确恢复状态 |
| 并发 Worker 数 | 默认硬上限 4，可配置但有安全上限 |

### 11.2 稳定性

- 8 小时运行测试中，无主进程崩溃。
- 连续执行 100 次小型子任务后，无持续增长的孤儿 Worker。
- 100 次启动/退出循环后，无有效会话被错误接管。
- 故障注入后，JSONL 不出现半行写入或无法解析的追加内容。

### 11.3 安全

- Renderer 无法直接读取任意文件、调用 shell 或获取凭据。
- 所有 IPC 参数经过运行时 schema 校验。
- 凭据保存在系统安全存储或受批准的安全机制中，SQLite 仅保存引用。
- 日志、审计、遥测和诊断包通过敏感信息扫描。
- 发布依赖无已知阻断级漏洞；严重级漏洞必须修复或书面接受并设置期限。

### 11.4 数据完整性

- Pi JSONL 只有持有会话租约的 Worker 可以写入。
- 产品元数据失败不得导致自动重写或截断 Pi JSONL。
- Worktree 删除必须基于实时 Git 状态检查，不只依赖 SQLite。
- 任何数据库迁移前自动创建可恢复备份。

## 12. 缺陷等级与发布阻断

| 等级 | 定义 | 发布规则 |
| --- | --- | --- |
| S0 阻断 | 数据损坏、凭据泄露、任意代码执行、错误删除项目、绕过租约写入 | 必须修复，立即停止发布 |
| S1 严重 | 核心流程不可用、频繁崩溃、任务状态错误、代理误路由 | 必须修复后重新验收 |
| S2 重要 | 有明确规避方案的功能缺陷或明显体验问题 | 需负责人批准并进入有期限计划 |
| S3 一般 | 不影响任务完成的视觉或文案问题 | 可进入后续版本 |

试点版本不允许存在任何 S0 或 S1 缺陷。

## 13. 验收证据

每个 P0 用例必须留存：

- 用例编号、应用版本、提交号和测试环境。
- 操作步骤或自动化测试名称。
- 实际结果、日志事件 ID 和关键截图。
- 涉及命令时记录命令、退出码和工作目录。
- 失败时记录缺陷编号和复测结果。
- 测试人和复核人。

模型自然语言输出不作为单独的通过证据；必须结合状态、文件差异、命令结果或可复现操作。

## 14. 发布签署

试点发布需要以下角色签署：

- 工程负责人：架构和技术门禁。
- 测试负责人：P0 用例和回归结果。
- 产品负责人：范围和用户体验。
- 安全/法务负责人：凭据、依赖和许可证。

任一签署人可以基于 S0/S1 问题提出 No-Go。带条件发布必须明确条件、影响客户、规避方案、负责人和截止日期。
